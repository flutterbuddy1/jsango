Introduction to JSango

JSango is a production-grade, batteries-included TypeScript backend framework inspired by Django’s convention-over-configuration philosophy, Laravel’s developer ergonomics, and modern high-concurrency JavaScript runtimes (Node.js 20+).

💡
Why JSango? In the JavaScript and TypeScript world, building a real-world backend traditionally requires assembling dozens of independent libraries for routing, ORM, migrations, auth, 2FA, admin dashboards, background queues, and telemetry. JSango solves this by providing a unified, strictly typed ecosystem with zero runtime reflection overhead.

Core Principles

1. Strict Type Safety

100% strict TypeScript throughout with compile-time query checking and zero any.

2. Batteries Included

Built-in ORM, Migrations, Auto-Admin SPA, 2FA, Session Tracking, Queues, and WebSockets.

3. Extreme Concurrency

Custom SegRadix Trie router executing >7,700,000 lookups/second with zero allocations on hot paths.

4. Security by Default

RFC 6238 TOTP 2FA, Scrypt password hashing, CSRF/CORS protections, and secure session management.

5-Minute Quickstart

You can scaffold and launch a fully functional JSango application in three simple steps.

1. Create a New Project

Terminal 
# Scaffold project with TypeScript configuration, ORM models, and Admin Panel
npx jsango new my-backend
cd my-backend
pnpm install
pnpm dev

2. Define Your Model & REST Route

Open src/index.ts to define your declarative model and HTTP routes with zero boilerplate:

src/index.ts 
import { createApp, model, fields } from 'jsango';

// 1. Strongly typed declarative ORM model
export const Product = model('Product', {
  id: fields.id(),
  name: fields.string({ maxLength: 255 }),
  price: fields.number(),
  inStock: fields.boolean({ defaultValue: true }),
});

// 2. High performance application instance
const app = createApp();

// Query products and return JSON directly (automatic serialization)
app.get('/api/products', async () => {
  return Product.where('inStock', true).get();
});

// Or generate full CRUD endpoints in 1 single line
app.crud('/api/crud/products', Product);

await app.listen(3000);
console.log('🚀 JSango running on http://localhost:3000');

3. Start Development Server

Terminal 
pnpm dev

SegRadix Trie Router

JSango features a custom Segment Radix Trie router built for extreme throughput and sub-millisecond route resolution.

Typed Route Parameters

Constrain parameters inline with built-in segment validators like :uuid, :int, and :slug:

Router Example 
// Automatically validates UUID format before triggering handler
app.get('/api/v1/users/:id:uuid', async (ctx) => {
  const userId = ctx.request.params['id'];
  const user = await User.query().findById(userId);
  return user ? ctx.response.json(user) : ctx.response.notFound();
});

Route Groups & Scoped Middleware

Route Groups 
app.group('/api/v1/admin', (router) => {
  router.use(requireAdminAuth);
  router.get('/analytics', analyticsHandler);
  router.post('/settings', settingsHandler);
});

Database Drivers & Multi-DB Management

JSango provides native, production-grade drivers for the most popular SQL and NoSQL database engines with zero-config in-memory fallback for rapid prototyping:

Driver Identifier Underlying Engine / Library Features Supported
PostgreSQL postgres, postgresql, pg Native pg Pool Transactions, Savepoints, RETURNING, SSL, Isolation Levels
MySQL / MariaDB mysql, mariadb Native mysql2/promise Connection Pooling, Auto-increment IDs, SSL, Transactions
SQLite sqlite, sqlite3 better-sqlite3 / node:sqlite Zero-config, In-Memory or File-backed, Transactions, Fast DDL
MongoDB mongodb, mongo Native mongodb Client Collections, Document CRUD, Transactions, Clustering
In-Memory memory Built-in Pure TypeScript Engine Default zero-config prototyping, Instant test suite execution

Configuring Multi-Database Connections

Configure multiple named databases in jsango.config.ts or directly on createApp():

jsango.config.ts 
import { defineConfig } from 'jsango';

export default defineConfig({
  database: {
    default: 'postgres',
    connections: {
      postgres: {
        driver: 'postgres',
        host: process.env.DB_HOST ?? 'localhost',
        port: 5432,
        database: 'my_production_db',
        username: process.env.DB_USER ?? 'postgres',
        password: process.env.DB_PASSWORD,
        pool: { min: 2, max: 20 },
      },
      analytics: {
        driver: 'mysql',
        url: process.env.MYSQL_URL,
      },
      cacheDb: {
        driver: 'sqlite',
        filename: './data/local.db',
      },
      documents: {
        driver: 'mongodb',
        url: 'mongodb://127.0.0.1:27017',
        database: 'analytics_docs',
      },
    },
  },
});

Declarative ORM & Relationships

JSango’s ORM combines compile-time type inference with an Abstract Syntax Tree (AST) query engine, connection pooling, and batch eager loading to completely eliminate N+1 queries.

Defining Models & Relations

src/models/user.ts 
import { defineModel, fields } from '@jsango/orm';

export const User = defineModel({
  name: 'User',
  table: 'users',
  fields: {
    id: fields.uuid({ primaryKey: true }),
    email: fields.string({ unique: true, maxLength: 255 }),
    fullName: fields.string(),
    role: fields.enum(['admin', 'editor', 'viewer']),
    isActive: fields.boolean({ default: true }),
  },
  relations: (rel) => ({
    orders: rel.hasMany('Order', { foreignKey: 'userId' }),
    profile: rel.hasOne('Profile', { foreignKey: 'userId' }),
  }),
});

Batch Eager Loading (No N+1)

Load related models efficiently with .with():

Querying with Relations 
const activeUsers = await User.query()
  .where('isActive', '=', true)
  .with('orders', (q) => q.where('status', '=', 'paid'))
  .orderBy('createdAt', 'desc')
  .limit(20);

for (const user of activeUsers) {
  console.log(user.fullName, user.orders.length);
}

Auto-Generated React Admin Console

Similar to Django's revered admin interface, JSango automatically generates a full-featured single-page application (SPA) with CRUD, search, faceted filters, batch bulk actions, CSV export, and RBAC security from your model schemas.

Defining an Admin Resource

src/admin/user-resource.ts 
import { createAdminResource } from '@jsango/admin-core';
import { User } from '../models/user.js';

export const UserAdminResource = createAdminResource(User, {
  label: 'User Accounts',
  icon: 'users',
  listFields: ['id', 'email', 'fullName', 'role', 'isActive'],
  searchFields: ['email', 'fullName'],
  filters: [
    { field: 'role', type: 'select', options: ['admin', 'editor', 'viewer'] },
    { field: 'isActive', type: 'boolean' }
  ],
  export: { csv: true, json: true },
});

Mounting the Admin Server

Mounting Admin 
import { AdminServer } from '@jsango/admin-server';
import { UserAdminResource } from './admin/user-resource.js';

const adminServer = new AdminServer({
  title: 'My Enterprise Dashboard',
  resources: [UserAdminResource],
  path: '/admin'
});

app.mount(adminServer);

Two-Step Auth (TOTP 2FA) & Sessions

Security is a first-class concern in JSango. It includes an RFC 6238 compliant Time-Based One-Time Password (TOTP) engine, active device session tracking, and remote session revocation.

2FA TOTP Service 
import { TotpService } from '@jsango/auth';

const totp = new TotpService();

// 1. Generate Base32 secret and otpauth:// URI
const secret = totp.generateSecret();
const qrUri = totp.generateKeyUri({
  secret,
  accountName: 'developer@example.com',
  issuer: 'JSango App'
});

// 2. Verify 6-digit token with sliding window
const isValid = totp.verifyToken({
  secret,
  token: '123456',
  window: 1
});

Background Job Queues & Events

Execute heavy background tasks reliably with automatic retries, dead-letter store management, and concurrent worker loops.

Defining & Dispatching Jobs 
import { defineJob } from '@jsango/queue';

export const ProcessPaymentJob = defineJob({
  name: 'process-payment',
  retryPolicy: { maxAttempts: 5, backoffMultiplier: 2 },
  async handler({ orderId, amount }) {
    await paymentGateway.charge(orderId, amount);
  }
});

// Dispatch job
await ProcessPaymentJob.dispatch({ orderId: 'ord_123', amount: 99.00 });

Realtime WebSockets

Multi-room WebSocket architecture with heartbeat monitoring, user identity binding, and backpressure management.

WebSocket Server 
import { WebSocketServer } from '@jsango/websocket';

const ws = new WebSocketServer({ path: '/realtime' });

ws.onConnection((socket, identity) => {
  socket.joinRoom(\`team:\${identity.teamId}\`);

  socket.on('message:send', (data) => {
    ws.broadcast(\`team:\${identity.teamId}\`, 'message:received', {
      user: identity.name,
      text: data.text
    });
  });
});

OpenAPI 3.1 & Swagger UI Documentation

JSango automatically generates compliant OpenAPI 3.1 JSON schemas by introspecting your route signatures, input validation schemas, and ORM models, and renders an interactive, high-contrast dark-themed Swagger UI dashboard out of the box.

1-Line Auto Documentation

src/index.ts 
import { createApp } from 'jsango';
import { Product } from './models/product.js';

const app = createApp();

// Mount CRUD routes
app.crud('/api/products', Product);

// Enable automated OpenAPI 3.1 spec and interactive Swagger UI docs
app.openapi({
  path: '/openapi.json',
  title: 'E-Commerce Store API',
  version: '2.0.0',
  description: 'Production REST API with real-time inventory and search',
});

await app.listen(3000);
// Interactive UI is live at: http://localhost:3000/docs
// OpenAPI JSON schema at: http://localhost:3000/openapi.json

CLI Commands Reference

The JSango CLI provides fast code generation and developer workflows:

Command Description
npx @jsango/cli create <name> Scaffold a new batteries-included JSango project.
npx @jsango/cli dev Start local development server with hot reloading.
npx @jsango/cli make:model <Name> Generate a typed ORM model definition.
npx @jsango/cli make:admin <Model> Generate an auto-admin resource definition.
npx @jsango/cli migrate Run pending database migrations.
npx @jsango/cli migrate:diff Diff ORM model schemas against database and generate migration file.
npx @jsango/cli openapi:generate Generate an OpenAPI 3.1 JSON / YAML specification document.
